二、本体模型：业务语义的理解基础
系统通过 operational-ontology 模块定义了一组核心本体概念，这些概念是"理解业务语义"的基石：

本体概念	代码位置	语义含义
Customer	modules/operational-ontology/.../Customer.java	客户主档：行业、规模、等级、风险、关系摘要
KycGapProfile	modules/operational-ontology/.../KycGapProfile.java	KYC缺口画像：已知/部分已知/未知项 + 优先问题
ProductKnowledgeCard	modules/operational-ontology/.../ProductKnowledgeCard.java	产品知识卡片：触发条件、关键条款、风险点
OpportunitySignal	modules/operational-ontology/.../OpportunitySignal.java	机会信号：Signal≠Opportunity（禁令#7）
ExternalEvent	modules/operational-ontology/.../ExternalEvent.java	外部事件：工商变更、诉讼等，带 possibleBusinessSignal
PolicyRule	modules/operational-ontology/.../PolicyRule.java	政策规则：禁令、严重度、逻辑描述
FactReconciliationCase	modules/operational-ontology/.../	事实对账：Claim≠Fact（禁令#6）
Commitment	modules/operational-ontology/.../	承诺：待履行的客户/RM承诺
核心本体约束（禁令体系）：

禁令#3: 不要承诺授信额度
禁令#6: Claim≠Fact — 客户陈述不是事实，必须经过对账
禁令#7: OpportunitySignal≠Opportunity — 信号不等于机会

private List<PrevisitReportContent.ProductScheme> matchProducts(
        Customer customer, CustomerOperatingView view,
        List<ProductKnowledgeCard> products, List<ExternalEvent> events) {
    return products.stream()
        .filter(p -> matchesTrigger(p, customer))      // 基于触发条件匹配
        .map(p -> new PrevisitReportContent.ProductScheme(
            p.productId(), p.name(), p.trigger(),
            estimateAmount(p, view), estimateTerm(p),
            p.keyConditions(), p.requiredMaterials(), p.riskPoints()))
        .toList();
}
匹配逻辑：ProductKnowledgeCard.trigger 包含行业/等级关键词，与 Customer.industry / Customer.customerTier 进行字符串匹配。

3.4 关键问题推导 — deriveKeyQuestions()

## -------------------------------------------------------------------------------------------
private List<String> deriveKeyQuestions(...) {
    List<String> questions = new ArrayList<>();
    kycGap.ifPresent(k -> questions.addAll(k.priorityQuestions()));   // KYC缺口优先问题
    events.stream()
        .filter(e -> e.possibleBusinessSignal() != null)
        .forEach(e -> questions.add("确认外部信号: " + e.title()));    // 外部事件信号
    openCommitments.stream()
        .filter(c -> c.status() == Commitment.CommitmentStatus.OPEN)
        .forEach(c -> questions.add("跟进承诺: " + c.content()));      // 未履行承诺
    return questions;
}
3.5 访问策略推导 — deriveVisitStrategy()

五、语义提取：本体模型理解业务语义的核心
SemanticPatternExtractionStrategy 是系统"理解业务语义"的核心引擎，它识别 8种语义模式：

模式	正则/LLM	置信度	本体映射
FINANCING_NEED	金额+意图关键词	0.50-0.80	OpportunitySignal(FINANCING_NEED)
COMMITMENT	"我会/承诺/保证"	0.85	CustomerCommitment / BankCommitment
RISK_SIGNAL	风险关键词	0.50-0.95	RiskIndicator
EXPANSION_INTENT	扩展/新增/增资	0.75	Intent(EXPANSION_INTENT)
MATERIAL_PROVIDE	提供资料/补充材料	0.80	CustomerCommitment(MATERIAL_PROVIDE)
FOLLOW_UP	下次/后续/跟进	0.70	BankCommitment(FOLLOW_UP)
CUSTOMER_STATEMENT	"我们公司目前营收..."	0.65	FactClaim → 必须对账
PRODUCT_INTEREST	产品/方案/利率	0.60	OpportunitySignal(FINANCING_NEED)
LLM优先+正则Fallback：先尝试LLM提取，失败时回退到8种正则模式。

九、关键设计决策
R1访前报告目前是纯本体驱动，未使用LLM — 因为客户上下文、KYC缺口、产品匹配都可以通过结构化数据精确推导，LLM的幻觉风险在此场景不可接受。

R8下次访前报告使用LLM增强 — 因为需要从上次访后分析中提炼"重点"和"建议"，这是LLM擅长的语义综合任务。

语义提取采用LLM+正则双保险 — LLM理解上下文更准确，但正则保证可用性。

事实对账委托DMN决策引擎 — 将对账规则从硬编码if-else外化到DMN模型，业务人员可调整规则而无需改代码。

所有CRM回写强制 require_human_confirm=true — 禁令#3的体现，AI不能直接修改CRM数据。
