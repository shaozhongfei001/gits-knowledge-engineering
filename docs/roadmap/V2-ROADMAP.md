## 2. 模块详细规划

### 2.1 M03 业务规则与指标口径配置

| 项目 | 内容 |
|------|------|
| **优先级** | P1 |
| **资源估算** | 3 人月 |
| **预估工期** | 6 周 |
| **依赖关系** | M18（声明与事实基线）、M22（评估评分） |
| **描述** | 提供业务规则的可视化配置界面和指标口径的统一定义能力，支持非技术用户自定义规则和指标计算逻辑 |

**功能范围**：
- 规则引擎管理界面（CRUD、版本控制、启用/禁用）
- 指标口径定义（计算公式、数据源映射、口径说明）
- 规则测试沙箱（模拟执行、结果预览）
- 规则变更审计日志

**与首期模块集成点**：
- M22 评估评分：规则配置后直接参与案例评分
- M18 声明基线：规则触发产生声明候选项
- M06 机会信号：规则匹配产生机会信号

**技术方案**：
- 前端：规则编辑器（Monaco Editor + 自定义DSL高亮）
- 后端：规则存储（JPA + 版本表）、规则执行（复用现有EvaluationService）
- DMN集成：复用P11已实现的DMN引擎基础设施

**风险评估**：
- 低风险：技术方案成熟，与现有架构兼容

### 2.2 M05 知识权限映射

| 项目 | 内容 |
|------|------|
| **优先级** | P1 |
| **资源估算** | 2 人月 |
| **预估工期** | 4 周 |
| **依赖关系** | M01（客户上下文）、M04（KYC洞察） |
| **描述** | 实现知识资产与用户角色的权限映射，确保敏感信息按需可见，符合合规要求 |

**功能范围**：
- 权限模型定义（角色-知识类型-操作矩阵）
- 知识资产分类标记（公开/内部/机密/绝密）
- 动态权限过滤（API响应中自动过滤不可见字段）
- 权限审计日志

**与首期模块集成点**：
- M01 客户画像：根据权限过滤客户敏感字段
- M04 KYC洞察：根据权限控制KYC信息可见性
- M17 关系报告：根据权限过滤报告内容

**技术方案**：
- 权限模型：RBAC + ABAC混合模型
- 过滤层：Spring AOP + 自定义注解 `@KnowledgeAccess`
- 存储：权限策略表 + Redis缓存

**风险评估**：
- 中风险：权限模型设计需与安全团队对齐，可能影响现有API响应结构

**功能范围**：
- 企业经营指标自动采集与计算
- 财务健康度评分模型
- 行业对标分析
- 经营趋势预测与预警
- 自动生成经营分析报告

**与首期模块集成点**：
- M01 客户画像：获取企业基本信息和财务数据

- M06 机会信号：经营异常产生信号

## 3. 分阶段实施计划

### 3.1 Phase 1：合规与风控基础（V2.0 Phase 1）

**时间**：V2.0 启动后 0-16 周  
**目标**：建立合规与风控基础能力，优先实现P0模块

| 模块 | 优先级 | 工期 | 开始周 | 结束周 |
|------|--------|------|--------|--------|
| M14 黑名单筛查智能体 | P0 | 8周 | W1 | W8 |
| M08 机构经营分析智能体 | P0 | 12周 | W1 | W12 |
| M10 国际证审单智能体 | P0 | 16周 | W1 | W16 |
| M09 机构客群结构分析智能体 | P0 | 10周 | W5 | W14 |

**里程碑**：
- W4：M14 黑名单筛查 Alpha（核心匹配功能）
- W8：M14 完成 + M08 Alpha
- W12：M08 完成 + M09 Alpha

## 7. 技术架构演进

### 7.1 智能体通用框架

为避免每个智能体重复建设，建议在 Phase 1 开始时先构建通用智能体框架：

```
AgentFramework
├── AgentPort (端口接口)
│   ├── analyze(context) → AnalysisResult
│   ├── recommend(context) → Recommendation[]
│   └── explain(result) → Explanation
├── BaseAgent (抽象基类)
│   ├── LLM调用封装
│   ├── 规则引擎集成
│   ├── 结果缓存
│   └── 降级策略
└── AgentRegistry (注册中心)
    ├── 智能体发现
    ├── 健康检查
    └── 负载均衡
```

### 7.2 数据架构演进

- **向量数据库**：为RAG场景引入Milvus/Weaviate
- **图数据库**：为知识图谱引入Neo4j（M19）
- **时序数据库**：为趋势分析引入InfluxDB（M08, M09）

### 7.3 前端架构演进

- **智能体交互组件**：通用对话式UI组件
- **可视化增强**：ECharts/D3.js 图表组件库
- **实时推送**：WebSocket + SSE 通知机制
